## Code & PR Rules

*   **Zero Dead Code:** no unused variables/imports, no leftover debug logs (`console.log`, `print`).
*   **No Placeholders:** no `// TODO: implement later` or `// ... rest of your code here` — write the whole block.
*   **Comments explain why, not what.**
*   **Single-Issue Focus:** one fix, bug, or feature = one branch = one PR. One PR = One Issue.
*   **Strict Scope Isolation:** the PR holds only the code for the change; PRD and UAT updates go to their Outline docs, not this repo.
*   **Keep the Diff Small:** **PROHIBITED:** running global JavaScript/Python auto-formatters that modify untouched lines. Pre-commit runs on changed files only; keep it that way.
*   **Frappe Schema Guard:** a PR that changes a DocType **MUST** include the `.json` generated by `bench export-doc`. Never hand-write or hand-edit DocType JSON.
*   **Target `develop`.** `version-15` and `version-16` are release branches, only fast-forwarded at a release. Squash merge only; `develop` requires CI `Server (Frappe version-15)`, `Server (Frappe version-16)` and `Frappe Linter` to pass.

## What This Project Is

`frappe_psak_id` (app title **PSAK ID**) is a **generic, open-source (AGPL-3.0) Frappe app**
that presents ERPNext's ledger in the Indonesian **PSAK 118** format (IFRS 18): the
statement of profit or loss with its categories and required subtotals, account mapping,
restated comparatives, review and finalisation, and later the other statements. It is
standalone and independently installable — not tied to any client. Requires ERPNext.

---

## Non-Negotiable Design Principles

1. **Generic** — zero client-specific code. No client names, no hardcoded accounts, amounts or business values.
2. **Configurable** — behaviour comes from policy, mapping and settings doctypes, never hardcoded logic.
3. **Presentation only** — never change Frappe/ERPNext core, journal entries, GL Entries or ERPNext's standard reports. Read the ledger; never write to it, and no `doc_events` on ERPNext accounting doctypes.
4. **Reconciles with ERPNext** — every statement total equals ERPNext's Profit and Loss / Trial Balance for the same company, period and filters, and a test proves it.
5. **v15 and v16 from one codebase** — Python 3.10 compatible; version differences only in `frappe_psak_id/compat.py`.
6. **Indonesian market focus, any company** — follows PSAK wording and rules, but the architecture works for any company with similar needs.
7. **Public repository** — nothing internal in git: no client or ticket details, real ledger data, hostnames, container/site names or credentials. Environment details live on Outline (Tech Context).

Violating these principles is a blocker. Raise it before implementing, not after.

## Development Methodology (STRICT)

**Language:** all PRD prose (Problem Statement, Business Rules, User Stories, notes) is
written in Bahasa Indonesia. Code, fieldnames, doctype names, and section headers that
mirror the PRD template stay as-is. Code, commits, PRs and repo docs are in English.

Every feature follows this exact sequence. **Do not skip steps.**

```
PRD written → reviewed/approved by product owner
  → Implementation (based on approved PRD only)
    → Autonomous UAT execution & validation loop
      → Sign-off → merge
```

**No feature code starts without an approved PRD on Outline.**

Task arrives without PRD → first output = PRD draft on Outline — not implementation.

### Docs live on Outline (not in this repo)

PRDs, UAT docs, references (BRD) and the Memory Bank live exclusively on Outline under
`ORGANISATION › 01 Thinkspedia › Projects › Active › frappe_psak_id` (`docs › PRDs`,
`docs › UAT`, `docs › references`, `Memory Bank` — find via `search_documents` with query
`'frappe_psak_id'`; doc IDs are in the stubs under `.memory-bank/`, `docs/prd/`, `docs/UAT/`).

* **Never** write PRD/UAT `.md` files into `docs/prd/` or `docs/UAT/` (pointer stubs only).
* **Never** write real content into `.memory-bank/*.md` — they stay pointer stubs.
* New PRD: start from `PRD-TEMPLATE` in `docs › PRDs`, Status `Draft`, next `PRD-NNN`. New UAT doc: next `UAT-NNN`.
* Memory Bank: fetch only the single doc needed (Active Context at start, Progress before

## UAT Automation

Browser click-throughs use the `agent-browser` CLI, **not** the Playwright MCP tool. A
scenario is `[Passed]` only with URL + DOM + DB-row proof, and for a statement also the
reconciliation to ERPNext's own report; any hidden 403/404/500 = FAIL. Full loop:
`docs/agents/uat-automation.md`.

## Tests

CI runs the whole suite on Frappe/ERPNext v15 and v16 for every PR. Locally run the
modules you changed, then the app (`bench --site <dev-site> run-tests --app frappe_psak_id`).
State what you ran and the result in the PR's Test section. Details: `docs/agents/testing.md`.

## Versioning (`frappe_psak_id/__init__.py`'s `__version__`)

Bump once per PR, per semver, in the same commit as the change; add a CHANGELOG.md entry
under `[Unreleased]`:

* **Patch** (`0.0.X`): bug fixes, permission/data corrections, doc-only and tooling changes.
* **Minor** (`0.X.0`): new features — a new doctype, report, workspace, statement, export.
* **Major** (`X.0.0`): breaking changes — dropping a Frappe version, removing/renaming a public doctype or whitelisted API.

## Translations

gettext, like ERPNext: English in code wrapped in `_()` / `__()`, `frappe_psak_id/locale/main.pot`
plus `id`, `zh`, `ja`, `ar` PO files. After changing a string run `bench generate-pot-file
--app frappe_psak_id` and `bench update-po-files --app frappe_psak_id`, fill at least the
Indonesian `msgstr`, and commit `locale/` — CI fails when it is stale. Placeholders, never
concatenated fragments. Arabic is RTL: CSS logical properties only.

## Naming Conventions

* **Module:** `PSAK ID` (folder `frappe_psak_id/psak_id/`). Add a new module only when the PRD calls for one; prefix it `PSAK ID`.
* **DocTypes:** prefix `PSAK ID` — e.g. `PSAK ID Account Mapping`, `PSAK ID Company Policy`.
* **Roles:** `PSAK ID - <Function> - <Level>` — e.g. `PSAK ID - Accounting - Staff`, `PSAK ID - CFO`.
* **Logo / apps screen:** `public/images/psak-id-logo.svg` via `add_to_apps_screen`. Never set `app_logo_url` (it replaces the site's Desk navbar logo).

## Session Start Checklist

1. Read this file (AGENTS.md) fully
2. Fetch the **Active Context** doc from Outline (`.memory-bank/activeContext.md` is just a pointer stub to it)
3. Fetch the **Progress** doc from Outline for what's done and what's next
4. Check `docs › PRDs` on Outline for PRDs in "Approved" status waiting for implementation — no local fallback; if Outline is unreachable, ask the user
5. Fetch **Tech Context** before touching the Dev bench; fetch the relevant rule doc(s) before writing code
6. Never start implementation without an Approved PRD

Chat output: Caveman mode per Outline rule `08-caveman-mode` (code, commits, PRs, docs written normal).
